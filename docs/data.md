# 数据约定

## 输入

`episodes.json` 的 `episodes` 列表每项需含 `split`、`session`、`hdf5`、`video`。仅接受 train/validation。相对路径以清单目录为基准，不以 shell 当前目录为基准。

- MP4 与 HDF5 帧一一对应，视频原生 PTS 必须有限且严格递增。
- `transforms/camera`：`[N,4,4]`，世界坐标系中的相机位姿。
- `transforms/{left,right}Hand` 及 `{left,right}{ThumbTip,IndexFingerTip,MiddleFingerTip,RingFingerTip,LittleFingerTip}`：`[N,4,4]`。
- `confidences/<part>`：`[N]`；缺失、非有限或低于 0.5 的观测被掩码，不填充为可信标签。
- 若 HDF5 有 `session_name` 属性，必须与清单一致；没有属性时由使用者提供准确的采集会话标识。工具无法从匿名文件自动推断真实会话。

工具拒绝跨集合重复会话、重复源文件路径或重复文件内容。它不会自动下载或选择数据子集。数据文件仍可能存在工具无法识别的参与者/场景重叠，研究者应按研究目标制定更严格划分。

## 目标与窗口

每只手 24 维：手腕 xyz（3）、旋转矩阵前两列（6）、五个指尖 xyz（15），左右拼成 48 维。所有位置与旋转都转换到**当前帧相机坐标系**，而非随未来相机逐帧变化的坐标系。

每个窗口 17 帧：当前状态 + 16 个未来目标。请求间隔 0.05 秒，最大预测时距 0.8 秒；选择最近原生帧，允许最大 0.025 秒偏差，不允许重复帧。默认每 10 个原生帧尝试一个锚点；`--stride` 可配置。

至少一只手当前手腕有效，且未来至少 13/16 帧手腕有效。手腕要求有效 SE(3) 与追踪置信度；指尖要求自身位置/齐次行有效及置信度达标，并依赖手腕有效性。相机锚点必须是有效 SE(3)。当前版本不要求指尖旋转有效，因为目标只使用其位置。

## 归一化与视觉

统计量仅在 train 的有效窗口坐标上拟合，重叠窗口会重复计入其观测。训练中从未出现的维度在全部集合中掩码；恒定但出现过的维度保留，尺度设为 1。无效值归一化后为 0，独立掩码仍保留。

仅编码每个窗口的当前图像。RGB 按比例缩放、居中黑边填充到 224×224，使用 ImageNet 均值/标准差。DINOv3 S/16 输出 196×384 patch tokens，编码计算为 FP32，缓存为 FP16；黑边 patch 仍参与注意力。当前帧在同一个 episode 中去重，`*_window_rows.npy` 保存窗口到缓存行的映射。

## 输出

- `manifest.json`：schema、源文件哈希、会话划分、编码器及其权重哈希、窗口参数、所有产物哈希。
- `normalization.json`：48 维均值/尺度/观测数/支持掩码。
- `*_episode_*.npz`：归一化值、有效性掩码、原生帧索引、视频原生 PTS、session。
- `*_features.npy` / `*_window_rows.npy`：视觉特征及映射。

准备失败会清理本次临时输出，不覆盖已有产物。数据加载默认核验全部产物哈希，数据较大时需留出读取时间。当前准备流程在内存中积累窗口与特征，适合精选子集；大规模数据需要进一步实现分片/流式缓存。
